# Accessibility statement

This repository holds a research paper, *Web Browsers as a Pervasive Accessibility
Solution*, and this statement describes the accessibility of the materials provided here.
Because the paper is about accessibility, the author intends these materials to meet a high
standard — and to say plainly where that standard is still being verified.

## Formats provided

The paper is available in three formats so you can choose the one that works best for you:

- **HTML (read online)** — an accessible web page, the recommended way to read the paper in
  a browser or with a screen reader.
- **Tagged PDF** — for reading offline or printing, with a tagged structure for assistive
  technology.
- **Microsoft Word (.docx)** — for reading, commenting, or tracked-change review.

All three contain the same content.

## Accessibility features

The author has aimed for these materials to conform to WCAG 2.2 Level AA and to be usable
with assistive technology. Specifically:

- **Document language** is set (en-US) in all formats.
- **Headings** use real, hierarchical heading styles (no skipped levels), so you can
  navigate by heading with a screen reader or the HTML page's structure.
- **Tables** use real header cells (`<th>` in HTML; header rows in the PDF/Word), with no
  merged cells or blank spacer rows in data tables.
- **Links** use descriptive link text rather than bare URLs or "click here."
- **Reading order** follows the visual order.
- **Color is not used as the only way to convey meaning**, and the HTML page supports both
  light and dark color schemes with sufficient text contrast.
- **The HTML page** includes a "skip to main content" link, semantic landmarks, a descriptive
  page title, and a responsive layout that works at phone width.
- **The PDF** is tagged, has a document title set in its properties, and sets the document
  language.
- **The Word document** uses built-in heading styles and a set document language.

## Known limitations

- This is a **review draft** (see the work-in-progress notice in the paper). The content is
  under peer review for accuracy, and the accessibility of the documents has been checked
  with automated structural tools but has **not yet had a full manual assistive-technology
  audit**. A manual check — screen-reader reading-order verification, table-header
  association, and alternative text review — is part of finalizing the paper.
- The paper currently contains **no images, charts, or figures**; it is text and data tables.
  If figures are added in a later version, they will include text alternatives.

## Requesting an alternative format or reporting a barrier

If any part of this paper is not accessible to you, or you need it in a different format,
please let the author know — accessibility feedback is especially welcome for a paper on this
topic. You can:

- Open an [issue](../../issues) in this repository, or
- Contact the author directly.

The author will do their best to provide an accessible alternative promptly.

## Standards referenced

- Web Content Accessibility Guidelines (WCAG) 2.2, Level AA
- PDF/UA (tagged PDF) for the PDF format
